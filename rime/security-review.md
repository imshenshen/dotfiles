## 建议优先处理

### 1. 统一敏感输入场景的云端隐私边界（高优先级）

`native/cloud_pinyin/cloud_pinyin.mm:333` 的云查询开关仅检查 Rime 的 `password`／`_password` 标志，没有直接检查 macOS Secure Event Input。这次检查也没有找到前端把系统安全输入状态同步到这两个标志的实现。不能据此认定所有密码框都会泄露，但对未正确提供字段类型的宿主，现有保护不足以作保证。

`native/voice/VoiceController.swift:214` 中，录音期间进入安全输入状态只会转为浮窗，音频采集与豆包识别继续。这符合当前“切换应用继续录音”的交互，却也意味着在密码管理器等场景说出的内容仍可能发往云端。

建议集中管理安全输入策略：安全输入时禁止云候选；听写应暂停或停止云端音频发送，并明确展示暂停状态。普通切换应用仍可继续录音。另提供按应用禁用云功能的设置。云候选默认已开启，普通拼音会分别发送给启用的服务；这属于既有功能的数据流，需要在设置中清楚说明，不能把 HTTPS 等同于服务商看不到输入。

### 2. 缩紧网络边界（中优先级）

`native/cloud_pinyin/cloud_pinyin.mm:30` 的重定向检查只要求 HTTPS，没有限制重定向域名。若服务端返回跨域重定向，输入内容可能随请求传到其他 HTTPS 主机。建议限制为原服务允许的域名，或直接拒绝重定向。

响应在完整下载后才由 `Parse` 检查 1 MiB 大小，下载过程仍可能积累过大响应。建议使用数据代理累计大小并及时取消；同时限制在途请求总数。现有 TLS、短超时、无持久 Cookie／URL 缓存和候选长度校验应保留。

### 3. 固定构建依赖与公共词库来源（中优先级）

`tools/build_squirrel.sh:52` 仍执行上游预设依赖／配方下载，尚未把所有下载内容固定到提交和摘要。前端提交与 Boost 摘要已固定，但不足以保证整个构建可复现。

`distribution/data/` 是约 74 MiB 的公共资源快照，保留了来源和授权信息；缺少每项资源的精确提交、摘要及完整依赖授权清单。建议生成依赖清单和 SHA-256 锁文件，校验下载，独立跟踪词库更新，避免每次提交产生难以审阅的大词库变更。

### 4. 把发布校验变成强制门槛（中优先级）

`tools/sign_squirrel_app.py:43` 起用 Python `assert` 检查证书身份和权限；优化模式会跳过这些断言。建议改为显式校验并失败退出。

`tools/package_squirrel.sh` 将包直接写到 `dist/` 后才执行后续步骤；后续失败可能留下看似可分发的产物。建议先输出临时目录，通过资源、签名、回归等门槛后再原子发布，并生成带版本的校验和。公证目前按用户要求关闭，应区分“已签名未公证”和“已公证”产物。

脚本替换构建目录应用时先删除再复制，可改为临时副本加原子重命名；虽然不影响已安装应用，失败时仍会损失当前构建副本。
